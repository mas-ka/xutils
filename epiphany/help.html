Epiphany - 操作マニュアル ＆ 仕様リファレンス

　Epiphany は、蛍光XAFS測定で得られた2次元スペクトログラムデータ（TIFF形式）を読み込み、事後的にROIを設定・調整して蛍光収量スペクトル（μt）を再計算し、9809形式のデータファイルとして書き出すためのツールです。

Spectrogram

　スペクトログラムデータの読み込み、2次元ヒートマップ表示、およびROIの設定を行います。

  • TIFファイルの読み込み: ツールバー右上の【】ボタンをクリックしてTIFFファイル（.tif, .tiff）を選択するか、カード上へ直接ファイルをドラッグ＆ドロップして読み込みます。
  • 9809ヘッダの表示: ツールバーの【】ボタンをクリックすると、TIFFファイル内に埋め込まれた9809形式のヘッダ情報をダイアログで確認できます。
  • ヒートマップ（左側パネル）:
    • 励起エネルギー（横軸）× 蛍光エネルギー（縦軸）における蛍光X線強度（CPS: count per second）を2次元カラーマップで表示します。
    • 下部のエネルギースライダーを動かすことで、注目する励起エネルギー位置（ヒートマップ内の青い縦カーソル）を変更できます。
  • ヒストグラム（右側パネル）:
    • 選択された励起エネルギーにおける「蛍光エネルギー（縦軸）× 蛍光強度（横軸）」の1次元エネルギースペクトルを表示します。
    • 右端の縦型レンジスライダーを動かして、蛍光ピークに対する ROI（積分範囲の下限・上限） を設定します。ROIの変更に伴い、ヒストグラム内の赤色塗りつぶし領域および下部のPost-productive μtスペクトルがリアルタイムに再計算・更新されます。
    • ヒストグラム上でマウスドラッグによるズーム操作が可能です。ズームしたエネルギー範囲に連動して左側のヒートマップも自動的に拡大表示されます（ダブルクリックで描画範囲をリセット）。

Post-productive μt

　設定されたROIに基づいて再計算された蛍光XAFSスペクトル（μt）の確認とエクスポートを行います。

  • μtスペクトルグラフ:
    • 横軸を励起エネルギー [eV]、縦軸を ROI内総カウント / I₀（規格化蛍光収量）としてプロットしたスペクトルを表示します。
    • グラフ右上のアクションバーから、PNG画像保存・ズーム・パン・範囲選択等の操作が可能です（ダブルクリックで描画範囲をリセット）。
  • 9809ファイルのエクスポート:
    • ツールバー右上の【】ボタンをクリックすると、現在のROI設定で積分・再計算されたデータを「9809形式のデータファイル（.dat）」としてダウンロード保存します。
    • 出力ファイル名には、設定されたROI範囲（例: _pp0120-0250.dat）が自動付与されます。

TIFF（スペクトログラム）データ構造仕様

　Epiphanyが処理する2次元スペクトログラムTIFFファイルの内部データフォーマット仕様です。

💡 TIFF形式の基本プロパティ:
  • ページ構成: シングルページ（多素子検出器では素子ごとに別ファイル）
  • ストリップ構成: 1ストリップ
  • 圧縮: なし（無圧縮）
  • ピクセルフォーマット: 32-bit IEEE float（いわゆる32ビットグレイ）
  • バイトオーダー: native（作成ホストマシン依存、通常はリトルエンディアン）
  • ImageDescription (Tag 270): 測定時の「9809」出力ファイルヘッダ部分（該当素子分）がテキストとして格納

1. 画素値のエンコード仕様（逆数格納）

　TIFF画像内の各画素値は、元の数値情報を逆数化して 0.0 〜 1.0 の小数値 として収められています。

　したがって、TIFFファイルから画素配列を読み込んだ後、再度逆数化（1.0 / pixel_value）を行うことで元の実数値を復元します。

💡 逆数格納の理由:
　32-bit IEEE float 形式の TIFF では画素値を 0.0 〜 1.0 の範囲で扱う仕様となっているため、実測データ（エネルギー値やカウント値など）をこの規格範囲内に収めて画像として正常に保持・互換性を確保する目的で、元の数値を逆数化して格納しています。
⚠️ 有効数字および丸め誤差に関する注意:
　数値を逆数化して 32-bit IEEE float（仮数部23ビット、十進有効数字 約6〜7桁）に格納し、復元時に再度逆数化を行うため、浮動小数点除算の丸めにより有効数字が約6桁程度に制限されます。
　通常の蛍光XAFS測定におけるカウント値（数十万カウント以下）やエネルギー値の実用上は十分な精度を保ちますが、厳密な整数カウント値等とは最下位桁で微小な差（丸め誤差）が生じ得る点に留意してください。

2. 画像サイズ（解像度）

  • 水平画素数（Width）: DSPのチャンネル数 + 8
  • 垂直画素数（Height）: 測定エネルギー点数 + 1

3. 画素データ配置（レイアウト）

【第0行: 全体ヘッダ行】

　画像データの1行目（水平インデックス y = 0）は、全体パラメータおよび各チャンネルの蛍光エネルギーが格納されます。

画素位置 [x] データ型 格納される情報・説明
[0, 1] Double (Float32 x2) 分光結晶の格子面間隔 d [Å]
[2] Float32 蛍光検出器の素子番号 detId（単一素子の場合は 1）
[3] Float32 バージョン番号 version（現行形式は 1、旧形式は 0）
[4, 5] Double (Float32 x2) I₀ 検出器のオフセット値 offsetI0
[6, 7] Float32 x2 予約領域（常に 0.0）
[8..] Float32 配列 各チャンネルの蛍光エネルギー値 [eV]

【第1行以降: 各測定点データ行】

　画像データの2行目以降（水平インデックス y = 1 〜 Height-1）は、各測定エネルギーにおける分光器角度およびスペクトルデータが格納されます。

画素位置 [x] データ型 格納される情報・説明
[0, 1] Double (Float32 x2) この測定点での分光器 θB 実測角度 [degree]
[2] Float32 蛍光検出器のリアルタイム t_real [sec.]
[3] Float32 蛍光検出器のライブタイム t_live [sec.]（取得不可時は 0.0）
[4, 5] Double (Float32 x2) オフセット減算済みの I₀ 検出器カウント値
[6, 7] Double (Float32 x2) ICR（Input Count Rate）総カウント値（取得不可時は 0.0）
[8..] Float32 配列 該当測定エネルギーにおける各チャンネルのカウント値 CNT [count]
※ CPS = CNT / treal

※ Double (Float32 x2) と表記された項目は、連続する2画素（Float32 各4バイト）をリトルエンディアンで結合した 64-bit IEEE double です。
